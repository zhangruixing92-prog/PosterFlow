# 重构方案：背景生成与元素合成解耦

> 目标：根治「图片变形、尤其人物变形」。把「图片生成问题」转为「排版工程问题」。
> 分支：`feature/v1`

## 1. 问题定位（基于现有代码）

当前流程（`generationPipeline.ts` → `imageGenerator.ts` → `canvas.ts`）：

```
整张主海报(含人物) ──► gpt-image-2-all 图生图(整图重绘) ──► 非等比拉伸到目标尺寸
```

两个**独立**的变形来源，均已在代码中坐实：

| 变形源 | 位置 | 本质 |
|---|---|---|
| ① 整图重绘（含人物） | `imageGenerator.ts:113` `image:[masterDataUrl]` 整图喂模型 | 模型逐像素重建，人脸/四肢被改写——**人物变形主因** |
| ② 宽高比分桶 + 非等比硬拉 | `imageGenerator.ts:82` 8 桶取近似 + `canvas.ts:53` `drawImage(img,0,0,W,H)` | 纯几何压扁/拉长，与模型无关 |

结论：让生成模型「逐像素保人物 + 换比例」本身自相矛盾。**元素必须脱离模型像素链路。**

## 2. 目标架构

核心原则：**背景 = 生成（只 outpaint），元素 = 像素级贴片（本地合成，永不进模型、永不拉伸）。**

```
主海报 + 框选图层
 ├─ [Stage0 一次] 资产切片：每个元素切成 PNG 贴片（固定资产）
 │                          + 抹除元素后的「背景底板」
 ├─ [Stage1 每尺寸] 背景生成：gpt-image-2-all 只把背景底板扩到目标比例
 │                          （prompt 禁止文字/人物/Logo）
 ├─ [Stage2 每尺寸] 布局规划：Qwen-VL 看主海报+尺寸+元素，输出每个元素的
 │                          目标归一化坐标/缩放（排版决策）；失败回退规则槽位
 └─ [Stage3 每尺寸] 本地合成：精确 W×H 画布
                     = 背景(cover 等比裁切) + 元素贴片(按布局坐标等比摆放)
                     ──► 最终成图（精确尺寸，零拉伸）
```

> **布局策略：Qwen-VL 辅助，而非纯规则。** 模型只输出**坐标与缩放比例**（数据），绝不碰像素；
> 合成仍在本地完成。规则槽位 (`layoutSlots`) 退居为**兜底**：Qwen-VL 不可用/返回非法/超时时使用。

消除两个变形源：
- 人物永不进模型 → 人物变形彻底消失；
- 全链路无非等比缩放 → 几何变形消失。

「元素不变」重新解读：**指元素自身像素不变，不是位置不变**。位置可重排（排版合理），内容不动 → 三个要求（人物不变 / 排版合理 / 不拉伸不裁切元素）同时成立。

## 3. 代码改动地图

### 新增模块
| 文件 | 职责 |
|---|---|
| `src/services/assetExtractor.ts` | 从 master+layers 切元素贴片 + 生成背景底板，返回 `{ sprites, backgroundPlate }` |
| `src/services/backgroundGenerator.ts` | 只做背景 outpaint（替代整图重绘） |
| `src/services/layoutPlanner.ts` | **Qwen-VL 布局规划**：输入主海报+尺寸+元素列表，返回每个元素的归一化布局框；含非法/缺失校验与规则兜底 |
| `src/engines/compositor.ts` | 本地画布合成（背景 + 贴片按布局框）→ 精确尺寸 dataUrl，纯像素执行层 |
| `src/config/layoutSlots.ts` | 三大尺寸族的**兜底**槽位/对齐/留白规则 + 元素类型→槽位映射（Qwen-VL 不可用时启用） |

布局规划复用 `qwenVision.ts` 现有的 `callVisionModelRaw` + `parseJSONSafe` 范式，新增一个函数：

```ts
// qwenVision.ts 新增
interface PlannedBox { type: LayerType; x: number; y: number; w: number; h: number } // 均为 0~1 归一化
export async function planLayoutWithVision(input: {
  masterImageDataUrl: string;
  sizeName: string; sizeWidth: number; sizeHeight: number; family: SizeFamily;
  elements: Array<{ type: LayerType; aspectRatio: number }>; // 贴片真实宽高比，约束模型只能等比缩放
}): Promise<PlannedBox[]>; // 返回每个元素在目标画布上的归一化位置；compositor 按 aspectRatio 等比落位
```

约束：模型只决定「放哪、多大」，**w/h 必须满足元素自身宽高比**（compositor 以 `min` 拟合，绝不非等比拉伸）；越界/重叠/缺失元素由 `layoutPlanner` 校正或回退规则。

### 修改模块
| 文件 | 改动 |
|---|---|
| `src/utils/canvas.ts` | 新增 `coverFitToDataUrl`（等比缩放 + 居中裁切）替换非等比拉伸；`resizeToDataUrl` 仅留给缩略图 |

### 数据模型补充
```ts
interface ElementSprite {
  id: string;
  type: LayerType;
  dataUrl: string;          // 切出的 PNG（Phase1 矩形，Phase2 透明）
  srcRect: CropRect;        // 在主图上的原始位置（用于推断相对布局）
  hasAlpha: boolean;
}
```

## 4. 关键风险与对策

| 风险 | 对策 |
|---|---|
| 矩形贴片在复杂背景上有「方块边缘」（尤其人物） | Phase1：贴片边缘羽化 + 要求 subject 处于较干净背景；Phase2：透明抠图（matting/SAM） |
| 背景 outpaint 仍会臆造文字/Logo | prompt 强约束「纯背景装饰、无文字无 Logo」；必要时先在底板上 inpaint 抹除文字区 |
| 极端比例（如 1005×136 Banner）元素塞不下 | 沿用 `applyFamilyStrategy` 跨类去主视觉规则；布局求解器支持缩小文字/丢弃次要元素 |
| 20 尺寸鲁棒性 | 布局求解器按族提供兜底；批量回归测试覆盖全部尺寸 |

## 6. 验收标准

1. 人物在所有尺寸下与主图**像素一致**（贴片直出，可像素比对）。
2. 任意尺寸无非等比拉伸（元素长宽比 = 主图长宽比）。
3. 文字/Logo 不被模型改写（不进模型）。
4. 三大族排版合理、不挤、留白自然。
5. 20 尺寸批量生成全通过。

## 7. 建议落地顺序

**先合 Phase 0**（几何止血，立竿见影、低风险）→ 再做 Phase 1/2（架构主体）→ Phase 3 验证 → Phase 4 视效果再决定是否上抠图。
